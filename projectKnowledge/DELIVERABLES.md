# Deliverables

Status: `todo` · `in-progress (<agent>)` · `blocked (<reason>)` · `done`
A deliverable is `done` only when every acceptance criterion passes and is verified by running it.

| ID | Deliverable | Acceptance criteria | Depends | Status |
|---|---|---|---|---|
| D0 | Foundation | Folders, knowledge docs, git repo, pnpm workspace, strict TS, Vitest runs | – | done |
| D1 | Circuit format v1 (`packages/format`) | Types for components, nodes, wires, params; validation with clear errors; version field + migration hook; tests | D0 | done |
| D2 | DC engine (`packages/engine`) | MNA solver: resistor, voltage/current source, ground, wire, switch; capacitor (open) and inductor (short) at DC. Plain-language errors (short circuit, no current path, not-yet-simulated part) and floating-part warnings. Golden tests: Ohm's law, voltage divider, KVL, series/parallel, current divider, Wheatstone bridge vs ngspice | D1 | done |
| D3 | Transient analysis | **D3a (done):** capacitor, inductor, switch, time stepping; AC and square sources; simulation settings in the file (format v2); engine runs in a Web Worker in `apps/web`; MCP `simulate_over_time` / `set_simulation`. Golden tests vs ngspice: RC charging, RL rise, RLC ringing, RC low-pass at its corner (all within 1%; RC within 0.003%). **D3b (done):** polarized capacitor, potentiometer, SPDT switch, lamp, transformer (vs ngspice K, within 1%), controlled sources E/G/H/F; palette grouped by category | D2 | done |
| D4 | Non-linear parts | Diode, Zener, LED, RGB LED, NPN/PNP, N/P-MOSFET (Newton–Raphson, junction limiting). Format v3 (diode/LED params, migration). Golden tests vs ngspice: diode drop, LED, NPN active + saturated, PNP, NMOS saturated + linear, PMOS, half-wave rectifier over time (all within 1%); robustness tests (diode across a battery, floating base/gate, bridge rectifier). App: symbols, LED/RGB glow; e2e transistor switch | D3 | done |
| D5 | Digital + mixed signal | Logic input/output, clock, voltage rail, NOT/AND/OR/NAND/NOR/XOR/XNOR, SR latches, D/T/JK flip-flops, 4-bit counter; thresholds at half the logic level (format v4 `logicHigh`); implicit ground. Tests: every gate's truth table, half and full adder from gates, counter + reset, flip-flop edges, NOR-gate latch memory, ring oscillator (and DC reports it), gate driving an LED, analog voltage read as a level. App: Logic tab, toggling inputs, lit indicators; e2e | D2 | done |
| D6 | Web UI MVP (`apps/web`) | Place, wire, move, rotate, delete parts; edit values (SI input like `4.7k`); click switches; undo; pause/resume; animated current; voltage colours; node voltages and part readings; plain-language errors/warnings. All edits via `packages/editing`. Unit tests (Vitest) + Playwright e2e. (Web Worker moved to D3: DC solves take well under a millisecond) | D2 | done |
| D7 | MCP server (`apps/mcp`) + shared edit commands (`packages/editing`) | Tools: list_component_types, create_circuit, add_component, remove_component, connect, disconnect, set_parameter, undo, get_circuit, simulate, probe, explain_circuit, open_circuit, save_circuit. Edits record author + undo. Tested from an MCP client (in-memory) and over real stdio; registered in `.mcp.json` | D2 | done |
| D8 | Live link | MCP edits appear live in the open web app (WebSocket); learner edits in the app reach the agent (`recent_changes`); one shared `CircuitDocument` and history, undo from either side; `open_in_app` link with session token; loopback + origin + token checks; app keeps working alone if the link closes. Unit tests + Playwright e2e driving the real MCP server over stdio | D6, D7 | done |
| D9 | Oscilloscope + ICs | **D9a (done):** scope probe + oscilloscope panel (worker samples ≤ 64 per frame, 4 real seconds window); op-amp (gain 100000, ±15 V, smooth limit); 555 timer. Tests: op-amp inverting/non-inverting/follower gain with finite-gain correction, rail limits, comparator; 555 astable period and duty against the exact charge/discharge times (and the datasheet formula within 2%), reset. **D9b (done):** 7-segment logic display, BCD-to-7-segment decoder (0–F), 4-bit ADC (truncating) and DAC, relay (series RL coil, pull-in/drop-out hysteresis); tests for every decoder code, ADC/DAC and round trip, relay pull-in time vs τ = L/R and hysteresis; e2e decoder → display | D4, D5, D6 | done |
| D10 | Save/load + PWA | Library dialog (save by name, open, delete; IndexedDB), open/download `.circuit.json` files (format checks + migrations, size limit), autosave and restore of the circuit being edited, installable PWA (manifest, own icon) working offline via Angular's service worker. Tests: file helpers (unit); e2e library round trip, reload restore, download + reopen, bad file explained; offline test that stops the server and reloads a production build | D6 | done |
| D11 | Desktop/mobile (`apps/desktop`) | Tauri builds for macOS, Windows, Linux; Android build | D10 | todo |
| D12 | Lessons + AI tutor | Lesson format; load_lesson / check_solution MCP tools; 5 starter lessons | D7, D9 | todo |
| D13 (opt) | Microcontrollers | AVR emulation running user code connected to circuit pins | D9 | todo |
| D14 (opt) | Backend | Spring Boot 4: accounts, community sharing | D10 | todo |

Parallel-safe once D2 is done: D3/D5 (engine, separate files), D6 (UI), D7 (MCP).
